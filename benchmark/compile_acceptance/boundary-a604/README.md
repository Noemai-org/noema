# Boundary recordings of the `requested_remedy` gate (A604)

Date: 24 Nov 2026 · Owner: Benchmark Owner (role agent) · For: C2 (the gate, UND-18, noema#932) · Status: **SYNTHETIC. Scripted replies, not live model output, never to be passed off as a live recording (A261).**

## What this is

`fixture/` is a directory in the format the compile acceptance run writes (`rec-NNNN.json` and `manifest.json`), so the replay provider (`replay.py`) and the fixture reduction (`fixtures.py`) read it as they read a live run's. It holds 148 files:
the compile route run once per boundary, 20 committed boundaries (23 in all), with an inner transport that answers from a script. No network, no key, no cost. The recorder wrote it; the model service's real pipeline, harness and provider adapter produced every request.

Each boundary changes one thing: the number the scripted "model" wrote as the probability of yes for the gate question (`requested_remedy_gate`). Each boundary is asked about a **different utterance** (the next item of the A604
labelled set, `benchmark/compile_acceptance/remedy_labelled.v1.json`), because a replay is keyed by the SHA-256 of the exact request and the gate's request is one fixed sentence: two boundaries on one utterance would be one request with two answers. The scripted answers do not depend on the label of the utterance.

`run_id` is `synthetic-boundary` in every file, and `recorded_at` is fixed (`2026-11-24T00:00:00Z`) so the output is the same on every run (INV-21; two runs were byte-identical). The manifest's label text is the recorder's own and says "recorded live output (SYNTHETIC)": read it with `run_id`; this directory is not live.

## The boundaries and what A612 expects

The expected outcome is computed from the text the provider wrote, by exact integer and fraction arithmetic and the rule of A612 (a plain decimal in [0, 1], floored to whole basis points, compared with the pack's threshold, 9000 basis points interim and a Founder decision to confirm; anything else, a missing value included, abstains). It does not read the implementation's answer. `boundary-findings.json` holds both, side by side.

| ID | Written | Expected | Why |
|---|---|---|---|
| B01 | 0.8999 | absent | one basis point below |
| B03, B04, B05 | 0.9, 0.90, 0.9000 | present | exactly the threshold, written three ways |
| B07 | 0.9001 | present | one above |
| B08 | 0.5 | absent | doubt |
| B09 | 0 | absent | zero as an integer |
| B10, B11 | 1, 1.0 | present | one |
| B13 | 1e-05 | absent | an exponent |
| B14 | 9e-1 | absent | an exponent for 0.9 |
| B15 | -0.1 | absent | a sign |
| B16, B17 | NaN, Infinity | absent | not finite numbers |
| B18, B19 | null, member missing | absent | missing |
| B20 | "0.95" (a string) | absent | a string where a number is required |
| B21 | 0.95 with "selected": "no" | absent | the model's own no |
| B22 | 0.6 with "selected": "yes" | absent | a yes at 0.6 is doubt |
| B23 | the option yes listed twice, each at 0.95 | stopped | a gate answer that repeats an option contradicts itself, so the harness refuses the whole reply (`OUTPUT_MISMATCH`, INV-02) and the compile ends with no proposal; no entry wins (A759) |

**Three boundaries are not committed:** B02 (a value just under 0.9 written to five places, which floors to 8999), B06 (just over 0.9 to five places, which floors to 9000) and B12 (just over one to five places, above one by less than a basis point). Their text holds five digits in a row, which the leak rule refuses in a committed file (REQ-SEC-003, A154). Generate them with `--include-long-digit-runs`. They matter: they are the floor-never-rounds-up boundary. SR ruled that the leak rule is not relaxed for them, so a test generates them (see below).

## Where the gate and A612's text agree

At the head named in each fixture file (main, with noema#932 merged) all 23 boundaries agree: **0 disagreements**. The 20 committed ones are in `boundary-findings.json`; B02, B06 and B12 are generated by a test (they write five or more digits in a row, which the leak rule flags in any committed file) and agree too. The earlier findings (an exponent form accepted as `0.9`; a malformed reply refused as a whole) were settled by A649: an exponent form is malformed, and the slot abstains. Nothing is hidden: the file lists every boundary.

## Use, and regeneration

`fixture/` is the reduced run (`fixtures.reduce_run`), flat (`manifest.json` and `rec-NNNN.json`, no sub-directory), and every file carries `fixture.synthetic: true`, which `ReplayTransport` requires (noema#938). C2 can run A604 offline: point the replay provider at `benchmark/compile_acceptance/boundary-a604/fixture`, and use `remedy_labelled.v1.json` for the labelled set. The findings file is outside the fixture directory on purpose.

**What replay serves, and what it does not.** Replay serves a usable recording by the SHA-256 of its request. 15 of the 20 committed gate recordings are usable. **B16, B17, B18, B19 and B20 are not**: a reply with NaN, Infinity, null, a missing member or a string where a number is required is refused as a whole by the harness, so the recording is a record of a failure (`usable_as_fixture: false`; rec-0094 and rec-0101 are `NOT_JSON`, rec-0108, rec-0115 and rec-0122 are `SCHEMA_MISMATCH`) and replay answers it with `ReplayRefused` code `EVIDENCE_ONLY`, never with the malformed text. That is by design, and a test pins it. Replay therefore cannot reproduce the `ABSENT` outcome of those five. Their outcome is exercised offline by the generator: `synthetic_boundary` runs the real compile pipeline against a scripted inner transport, with no network and no key, and compares each boundary with A612's rule (the test that runs it checks all 22, 0 disagreements). C2 runs those five through the generator, not through replay.

**B23 is the opposite case (A759).** Its recording is labelled `usable_as_fixture: true` (the reply is valid against the request's schema, and it answers exactly the questions asked), so replay serves it, and the harness then refuses the reply as a whole because it lists the option yes twice. Replay therefore reproduces that refusal offline, with no generator needed: the compile stops with no proposal (`ProviderUnavailable`).

Reproduce (the request bytes depend on the model service's code and the pack's `slot_gates`, so regenerate after either changes):

```
PYTHONPATH=services/model:. python3 -c "import sys; from benchmark.compile_acceptance.synthetic_boundary import main; sys.exit(main(['--out', 'DIR']))"
```

then reduce `DIR/recordings` with `fixtures.reduce_run(src, dst, head_sha=<the commit>)`. The script exits 1 when any boundary disagrees. Add `--include-long-digit-runs` to generate B02, B06 and B12 (not for a committed file). The recorded date is fixed, so two runs are byte-identical (INV-21).
