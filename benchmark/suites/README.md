# benchmark/suites

**Implements:** REQ-BEN-004, REQ-TST-005 (task BEN-29). **Owning track:** T4 (benchmark owner). **Updated:** 2026-11-03.

One command per named suite: `us`, `chaos`, `evil`, `full`. Each selects its cases from the generated suite, runs them through the runner (the public API only), scores exactly those cases and writes `suite-run.json` with the run ID. Generated layer only; it refuses any argument or environment value that names `benchmark-heldout` (INV-22, REQ-AGT-004). The held-out layer and the hidden-oracle release run belong to the benchmark owner (BEN-26, BEN-28) and are not run here.

```
make bench-us        # or bench-chaos, bench-evil, bench-full: make reset, generate, select, run, score, record
python -m benchmark.suites list us --suite benchmark/out/suite
python -m benchmark.suites run us --suite benchmark/out/suite --out benchmark/out/us --run-id g3-us-1 --reset-done [--commit-sha SHA] [-- runner options]
```

`make` variables: `BENCH_SUITE_RUN_ID` (default: suite name and UTC time), `BENCH_RESET=0` (skip `make reset`; the record then says `reset_done: false`), `BENCH_SUITE_ARGS` (runner options). Exit codes as `make bench`: 0 complete and Tier 0 all zero; 1 incomplete or a gate not zero; 2 bad input; 3 not run, no access (nothing faked, nothing scored).

A selector key nobody knows, an empty cell (`each_must_match`), an empty selection or a suite below `min_cases` is an error, never a quiet pass. Selection is a pure function of the manifest (and the case files, for families); the same suite gives the same ids and the same `selection_digest`.

## The G1 evidence run (BEN-05), pre-staged

`make bench-g1` (the tested Python in `g1.py`, not shell) runs the `g1` suite twice, each leg from `make reset`, with its own run ID (`<id>-a`, `<id>-b`) and the same commit, then `python -m benchmark.replay` (noema#102) diffs the Trust decisions and verdicts with `--exclude-mutated`, which removes only the named open exclusion `BEN-CLEAN-1007` (a Tushe-held fault) and reports "5 of 6 cases". Output in `$(BENCH_OUT)/g1/{a,b,replay}` and `g1-evidence.json`. **The evidence is labelled with its data source** (`BENCH_G1_DATA_SOURCE`, default `stand-in`: Founder's decision of 4 Nov 2026, Option B): a stand-in headline reads "G1 evidence (STAND-IN data, not Tushe): IDENTICAL on 5 of 6 cases (1 open exclusion)" and `rerun_against_tushe_required` is true; the same scenarios rerun against live Tushe once its OpenAPI is frozen. Only a clean run whose replay is IDENTICAL is evidence (`is_evidence`); NOT RUN, a failed leg or a replay that is not identical is not, whatever the label. It needs OUT-01 and REC-03 on `main` and the environment; until then each leg is NOT_RUN and the target stops at exit 3. The target needs `benchmark/replay`, which is on `main` once #102 merges. Every failure is kept: a leg that exits 1 (incomplete, or a Tier 0 gate not zero) does not stop the run, so the replay report is still written, but the whole run exits 1; a leg that did not run (3) or had bad input (2) stops it at once. A rerun is a new pair with its own ID; nothing is rerun selectively.

## What is recorded (`suite-run.json`)

Suite name, run ID, status (`NOT_RUN`, `COMPLETE`, `INCOMPLETE_OR_GATE_NOT_ZERO`, `INPUT_ERROR`), whether the caller said `make reset` ran (`reset_done`, recorded and not checked), the number of cases selected and their digest, the suite manifest digest, the seed, the generator, the commit, and the runner and scorer exit codes. The scored subset is in `subset/` (cases, oracles and a valid suite manifest for just those cases) and the scorecard and report in `score/`.

## Limits (stated, not hidden)

- Nothing here has run against a live environment: the runner reports "not run, no access" until a core, a fixture loader and the oracle counters exist, and these suites inherit that. Local run, 3 Nov 2026: all four suites exit 3 and record `NOT_RUN`.
- `make bench-*` was read and its recipe run step by step, but the target itself was not executed in the authoring session (its `make reset` step destroys the local Compose project, and the session's safety check blocked running `make` here).
- The "chaos matrix" of SEC-10 (each dependency down at each step) is not generated by this package. When its cases exist and carry FAULT tags they join the `chaos` suite with no change here.
- "At least 300 hidden-oracle cases" holds by construction for the generated layer (every case has an oracle document the runtime cannot read, checked at run time by the oracle counters); the held-out count (at least 100) is the benchmark owner's.

## Tests

`make bench-test`: `test_select.py` (selection, empty cells, short suites, the four real suites against the generated suite), `test_subset_and_run.py` (the scored subset, the command, NOT_RUN recording, the held-out refusal) and the runner's `--only-file` tests.

## A reset brings the environment back, and a retry keeps the earlier evidence (Codex on noema#117)

- `make reset` destroys the local Compose project (containers, networks, the data volume). A suite or G1 run that resets therefore runs `make $(BENCH_UP)` next (default `model-bench-up`: the bench stack with the model writing cost records, started with `--wait` so it is healthy before the runner starts). `BENCH_UP` can name another target. The G1 legs do the same before each leg (`g1.reset_and_up`). A failed reset stops before anything starts; a failed start is the run's exit code, never a pass.
- A run writes into one output directory (`benchmark/out/<suite>`, `benchmark/out/g1`). If that directory already holds an earlier run, it is first moved whole to a sibling named by the run ID it recorded (`benchmark/out/us.us-20261107T090000Z`), and the run prints where. Nothing is deleted, a retry with a new run ID cannot destroy the run before it, and no older score or replay file can sit beside a new record. The G1 suite is generated into `benchmark/out/g1-suite`, outside the directory that is archived.
