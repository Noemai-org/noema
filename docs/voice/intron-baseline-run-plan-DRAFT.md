It sets no threshold of its own: every value below is the Architect's (A380), passed to the code as an argument with no default in code (AGENT-16). Every vendor limit named here is in `docs/voice/intron-docs-notes-DRAFT.md` (noema#625) with its source page; none is repeated as a number in this plan.

## 1. What the run is, and is not

- It runs on Intron's **current** streaming endpoints and measures, for each short push-to-talk utterance, the accuracy of the transcript and the time of each stage of one voice turn: speech-to-text (end of speech to final transcript), the response stage, and text-to-speech (answer text to the first audio chunk). It is the **baseline**: it is recorded as measured. The latency verdict against the 1.8 s target is taken on Intron's real-time endpoints when they are enabled (A324).
- **Data terms (A377 to A379):** Intron's email of 18 November is the data terms of record for the POC, and no further agreement is a precondition for any work, including audio of real speakers. What the email says is **Intron's statement, not verified by us**: retention is set by the customer and is zero days by default (the account's retention is set to zero days), Intron does not train on customer audio or transcripts, and processing runs on AWS in Ireland.
- **Audio used:** synthetic audio, labelled SYNTHETIC (AGENT-25), generated by Intron text-to-speech from scripts we write; and recordings of consenting members of the team. **Raw audio lives only in the private store of the bench host (noema#819: one directory, mode 0700, owned by one dedicated account, laid out `<store>/<speaker_ref>/<file>` with files 0600 and folders 0700) and is deleted per the recording plan (noema#201, REQ-VOI-004): 90 days after analysis, counted per file from the modification time the runner sets to the analysis date; the deletion log is counts only. Only the Founders and the runner (a process running as that account) can read it; no agent session does, and no CI identity ever has access. It is never in the repository, never in a CI artifact, never in a log or a report.**
- **Budget:** free credits only, no spend, and no custom voice (declined, A377 to A379). Of the 60 free minutes, 20 are for this baseline on the current endpoints (accuracy on short push-to-talk utterances) and 40 are kept for the new real-time endpoints (latency).

## 3. The manifest (what is sent)

- **Utterances:** a fixed list, each 5 to 15 seconds when spoken (the Founder's measurement condition, passed to the harness as data). Locales: Nigerian English and Nigerian Pidgin, plus English mixed with Yoruba, Igbo and Hausa. Two kinds of audio: (a) scripts of a few sentences of a banking-style request (a transfer, a balance, a dispute) made into audio by Intron text-to-speech once and stored as SYNTHETIC fixtures; (b) the same kinds of request read aloud by consenting members of the team, recorded on the target devices where possible (speaker mix, accents, noise and devices are VOI-05's). Digits appear only as short key values (an amount, the last four digits of a reference).
- **What is asked of Intron in the technical session:** which voices exist for Nigerian English and Pidgin, whether streaming speech-to-text returns any per-token confidence, and how model releases are communicated (Intron has said models are upgraded automatically, so there is no version to pin). Until answered, the run records the model version as "not reported" and every token as low confidence (A173, A228).
- **Caveat the report states:** audio made by one text-to-speech voice is not Nigerian speech in the field, and a few team members are not the speaker mix of the field study. The baseline measures what it measures and says so.

## 4. The budget, before any call

The budget is 20 audio-minutes in total, counting three things together: the minutes of audio Intron text-to-speech generates for the synthetic fixtures, the minutes of audio sent to speech-to-text, and the minutes of answers spoken by text-to-speech (A380). The harness refuses a session whose audio does not fit (`AudioBudget`). Before the first call the runner prints, from the manifest, the three figures and their sum against the 20. A manifest that would exceed the total is **trimmed from its end, never by shortening an utterance**. The run uses free credits only; a refusal for lack of credit ends the run and nothing is bought.

## 5. The settings (A380: bench values for the baseline only, arguments, no default in code)

| Setting | Value |
|---|---|
| Speech-to-text final transcript, deadline | 20 s |
| Response stand-in, deadline | 1 s |
| Text-to-speech first audio, deadline | 10 s |
| Whole session, deadline | 40 s |
| `read_s` / `close_s` / `hold_s` | 2 s / 1 s / 5 s |
| Concurrency | 1 (one session at a time) |
| Pause between sessions | the larger of 2 s and the minimum that Intron's published limit on new connections per minute allows, computed from the sourced figure in the notes file |

A refused connection is never retried with a new connection inside the same session. A quota refusal (`RATE_LIMITED`) ends the session as an incomplete one and ends the run.

## 6. What the run does, step by step

1. Read the key from the file at call time (never from the environment, never logged).
2. Generate the synthetic audio once (section 3a), store it in the private store, and stop if any generation fails.
3. For each manifest line, in order: one `measure_session` call: speech-to-text on the stored audio, the response stage, text-to-speech to the first chunk. The response stage during the baseline is a fixed stand-in that returns a masked sentence of the same shape as a real answer; the real core's own latency is measured separately and shown as a separate row.
4. A session that fails at any stage is kept as an incomplete session with its failure kind. It counts as the worst case in the 95th percentile and is never dropped (`latency.py`).
5. After the last line, or at the first `RATE_LIMITED`, write the report.

## 7. The report (what is written, and what is not)

- Per stage and for the total: the number of sessions, complete and incomplete, the median and the 95th percentile of the complete ones, and the 95th percentile counting each incomplete one as the worst case. For the recordings of team members, the transcript accuracy against the script, counted by Voice from the transcripts, and nowhere else. The 1.8 s target is printed beside the total as a fact of the plan and no verdict word is written next to a baseline on the current endpoints.
- The failures by kind, with counts. **No audio, no transcript text and no key appears in the report, the log or any CI artifact**; a session is named by its manifest label.
- The budget spent, in audio-minutes, in each of the three directions, against the 20.
- The caveats of section 3 and the endpoint version in use as Intron reports it, or "not reported".

## 8. Stop conditions

Stop the run, write down what happened, and ask when: the key file is refused by the reader; any audio would leave the private store of the bench host other than to Intron's inference host; the budget would be exceeded; a refused connection or quota message appears twice in a row; Intron's response contains anything the adapter does not understand twice in a row (the wire format is one file per direction, `intron_wire.py` and `intron_tts_wire.py`; the first live call may show that a field is spelled differently from the documentation, which is a one-file change and its test).
