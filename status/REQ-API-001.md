# Session 2026-11-14 · REQ-API-001 · the A187 push (rulings A187 and A194, Security Reviewer's items 1 to 3 on noema#521)

## Session summary
- What changed (noema#521): (1) **Digit guard.** Every free-text member of the four public contracts and of the new `errors.v3` carries one pattern: five digits of any script (every Unicode decimal digit, category Nd), with at most one separator (the model redactor's set, noema#468) between two digits. It is written as literal characters so Python's `re`, Go, Pydantic and a JavaScript RegExp with the `u` flag read the same pattern; `test_public_api.py` rebuilds the class from `unicodedata` (Python 3.13, Unicode 15.1), so an upgrade that adds digits fails there. (2) **Public stage.** `investigation-response.v1` `state` and the SSE `progress` `state` are one of six values (`UNDERSTANDING`, `CHECKING`, `NEEDS_YOU`, `ACTING`, `HANDED_TO_TEAM`, `FINISHED`); no internal state name remains in any schema, fixture or generated type (tested). The values are the author's choice under A187 ("six or fewer"); the frontend owner owns the strings and the core owns the mapping. (3) **One not-found shape.** New `errors.v3.json` (`errors.v2` without `TENANT_SCOPE_MISMATCH`; `details[].field` guarded and `details` bounded at 20): the SSE error event uses it. `errors.v2` is unchanged. (4) **`case_ref_masked`** shows at most four digits in all. (5) `main` merged in; generated files regenerated, not hand-edited.
- Why: the Security Reviewer's P2 and items 1 to 3 on noema#521; A187 (committed in docs#169) and A194 (relayed; the Architect: the digit and separator definition lives in one place, `record/payloadguard`, and this contract mirrors its digit-and-separator reading).
- Risks, and how they are contained: **(a) the guard is a last line, not the masking**: masking is the producers' duty (A184); a number written with letters between its digits, or in words, still passes. **(b) it can over-refuse**: a date such as `12-05-2026` has eight digits joined by single hyphens and is refused, as the explanation validator and the model redactor already treat it; the core must send dates in a form without such runs. **(c) the reading of "four digits only" for `case_ref_masked`** is the literal one (at most four digits in all); the explanation facts' example `CMP-2026-…0001` shows eight and would be refused by the public contract: the core must format the public reference without the year. If the Architect meant "the last four of the number", the pattern is one line (`DIGIT_RUN`). **(d) `errors.v3` is not yet what the edge emits**: the edge's own error responses still use `errors.v2`, so a `TENANT_SCOPE_MISMATCH` could leave the edge until the edge owner (C1) moves it; the SSE error event cannot carry it.
- Tests added (REQ-API-001, REQ-UI-001, REQ-UI-002, REQ-SEC-003, AGENT-13, AGENT-15): `tools/contracts/test_public_api.py` (public stage, no internal state named, the digit class recomputed, the pattern against refuse and accept lists in four scripts and with separators, the case reference, the errors.v3 partition and guard, the SSE error body); 14 new fixtures (invalid: internal state, Arabic-Indic, full-width, separated, no-break-space and non-breaking-hyphen digits, the year and last four; `errors.v3`: tenant-scope mismatch, a digit run in `details[].field`, Arabic-Indic digits in a message, 21 details; valid: three public stages, `errors.v3` bodies, an SSE not-found error). Red first at `5ab1ddc7`.
