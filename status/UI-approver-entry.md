## Route and role boundary, from the committed specs and code only (nothing decided here)
- PERD v1.23 (current; v1.24 is Proposed and has the same row), §39.2 "Public API (partner app → core)": `POST /v1/confirmations/{confirmation_request_id}` | "ACCEPT or DECLINE" | request `{request_id, response: ACCEPT|DECLINE}` | `202 {state}` | "Approver from the session; REQ-TRU-009". It sits in the public table, with the customer routes; §39.4 (ops, audit, control plane) does not list it, and its role column is not given for this route. REQ-SEC-001: "`roles` holds exactly one of `customer`, `ops`, `approver`, `audit` ... No identity claim is read from a request body ... The token's `sub` is the only principal source."
- REQ-TRU-009: "The confirmation event's principal comes from authentication; a mismatch with `approver_requirement` raises `APPROVER_NOT_ELIGIBLE`"; "For MAKER_CHECKER, the approver must differ from the requester"; "ACCEPT triggers a fresh evaluation ... A mismatch produces a new decision, never a grant."
- A341 (interim, relayed, not committed; text in the scratchpad file): "Route checks: the `cfr_` pattern on `request_id`. A customer may answer only a SELF request where the session principal is the requester. Anyone else needs the approver role." Also: "One answer per request: enforced by the database, UNIQUE (tenant_id, request_id). The first answer wins and a later one gets 409"; "Who records CONFIRMATION_RECEIVED: ... the store (noema#756) ... The route does not append it."
- Code: `services/core/edge/refuse_test.go` lists `"POST /v1/confirmations/{confirmation_request_id}"` among the public routes the edge accepts. `services/core/edge/authz_matrix_test.go` (`mxRows`, PERD 39.4 rows 8 to 12) has no row for this route, and `docs/security/control-plane-authz-matrix.md` (docs repo) mentions the approver only as the actor C2 ("session token, role `approver`, tenant T") and has no row for the route. `services/core/edge/session/confirmation_answer_body_test.go` mounts the guard on `/v1/confirmations/answer` (a test path, not the PERD's) and says: "The approver's principal, roles, channel and time come from the authenticated session, never from the body"; `RefuseBodyIdentity` refuses a body naming an identity with 400 INPUT_INVALID.
- noema#754's design (route `POST /v1/confirmations/{confirmation_request_id}`; roles approver and customer-for-SELF; identity from the session only) is as relayed by C1; I could not read the PR and it is not in the repository.
- Tension to flag (not decided): the roles are approver, and a customer for a SELF request (A341). The customer overlay shows the confirmation card (`overlay-card.v1`, `confirmation_request_id`). If a customer page sends the answer for a SELF request, that page must import `approver.ts`, which this entry point is built to keep out of `customer.ts`. Whether the customer overlay sends it, or only approver pages do, is a decision for the Architect and the Frontend Engineer; the test allowlist `APPROVER_PAGES` in `ui/test/approver_contracts.test.mjs` is where such a page is named, in a reviewed change.
