**Silences of the ruling (A332), each decided by the safer reading.**
1. A version N+1 of an intent: the ruling says only "1 at creation". Every insert is epoch 1. No increment path exists, and a higher epoch would change what Trust treats as "the same complaint".
2. Column shape: `integer NOT NULL DEFAULT 1` plus `CHECK (logical_resolution_epoch = 1)`. The ruling gives no ceiling; the CHECK is the smallest state space until the increment path is designed (that migration replaces it). The DEFAULT is needed to back-fill the rows stored since 0026 (they were created before the column, so 1) and keeps the raw inserts of other tests (`orchestrator/portadapters/trust/evidence_db_test.go`) valid without edits outside this PR's allowlist.
3. `Save` and a caller-stated epoch: 0 (not stated) or 1 is accepted and stored as 1; anything else is refused before the event is appended. The alternative, ignoring the field, would hide a caller's mistake.
4. The epoch is not added to the `INTENT_ADMITTED` payload or to any contract (AGENT-15: no contract change in this PR); the Record event carries the version and hash as before.
5. `migrations/README.md` is not touched (A151 status: "Do not touch ... (A145)"), so the file list there does not name 0033; this README and the status file do.
