## What the requirements say

- **REQ-INP-004.** A follow-up (a clarification answer, a contradiction or a new request) is bound to the open investigation by `conversation_ref`, and is accepted only if the authenticated principal equals the investigation's principal. Understanding compiles the turn **in the context of the open Intent Object** and emits version N+1 with `supersedes`. A principal mismatch is treated as not found and raises a security event. An investigation in a terminal state starts a new one that links the old one `[REC]`. Audit event: `INVESTIGATION_RESUMED`. Acceptance: a resumed decision uses only evidence read after the resume (US-11).
- **REQ-INT-004.** Every change of meaning produces a new version with `supersedes`. Admitted versions are immutable. Only the latest admitted version may be evaluated. Version N+1 voids any decision, grant or confirmation tied to N (`INTENT_SUPERSEDED`). A concurrent supersession of the same version is resolved by optimistic locking on `(intent_id, version)`; the loser is recompiled. Audit: `INTENT_ADMITTED` (N+1) and `GRANT_VOIDED` (reason `INTENT_SUPERSEDED`). Acceptance: no grant is spent whose `intent_hash` is not the latest admitted version's hash; the Record links every version.
- **PUS-08.** "It was 50k, not 20k": the flag `CONTRADICTS_PRIOR_TURN` is raised, a new version supersedes the old, candidates are recomputed, and the decision uses only the latest version.

## Proposed design

**1. Binding (edge).** A follow-up arrives as a turn with `conversation_ref` set. The edge resolves it, in one transaction, to the open investigation and its latest admitted intent **under the verified session's tenant and principal**. No row, a row of another principal, or a row of another tenant gives the same answer, "not found", and a security event (REQ-INP-004; no oracle for which). The principal is taken only from the session (INV-12), never from the turn.

**2. Terminal state.** If the investigation is in a terminal state, the turn starts a new investigation whose first Record event links the old one `[REC]`. **Ruled (A320, A404):** a terminal-state follow-up is refused and the customer is asked for a new request, until a decision record says otherwise.

**3. Compile (no contract change).** **Ruled (A320, A404): no `prior_intent` contract change.** The compile request keeps its present shape. The first version of this note proposed one optional member, `prior_intent`; that proposal is withdrawn. The rulings do not say how Understanding compiles "in the context of the open Intent Object" (REQ-INP-004) without such a member. Decision 6 takes the safer default, the only path found that needs no contract change: the core compiles the follow-up turn alone, and the gate compares it with N (design 5) and completes it from N (design 8). This is **the author's safer default, for the Architect to confirm**; A666 did not cover it.

**4. Supersession.** The compiler's proposal for the turn becomes version N+1 with `supersedes = <intent_id>@N`, written through the existing admitted-intent store, **under the chain's correlation id (decision 7)**. A concurrent supersession of the same version is resolved by optimistic locking on `(intent_id, version)`, and the loser is recompiled (REQ-INT-004, exactly as the PERD states it). Admitted versions are never updated. The first version of this note added a rule that the loser recompiles once and that a second loss is a refusal with a retryable code; **that rule is removed: the PERD does not state it and no ruling gives it** (nothing here invents a retry count or a code).

**5. Contradiction flag.** **Ruled (A320, A404): the contradiction rule is deterministic in the gate, and the model's flag is advisory.** `CONTRADICTS_PRIOR_TURN` is decided by the gate: it is accepted only if the pack lists it and a value the new turn itself names differs from N's value in a slot N had resolved (INV-02). The comparison is made on the slots the new turn names, before the copy of design 8; a slot the new turn does not name is never a difference. The model's yes/no, where the model can see anything of the prior turn, adds a signal and decides nothing.

**6. Voiding.** **Ruled (A320, A404): no eager void (Founders' Block D, D8: lazy refusal at spend and execute).** Admitting N+1 does not rewrite or void N's decision, grant or confirmation. A grant minted under N is refused when it is spent or executed, because its `intent_hash` is not the latest admitted version's (REQ-INT-004 acceptance; PERD §28.2 E4: execution voids). The first version of this note voided N's grants in the admit transaction; that step is removed. The refusal at spend is to be confirmed by a test against the real controller, not assumed.

**7. Evidence after the resume.** US-11 requires that a resumed decision uses only evidence read after the resume. The Evidence port already reads per investigation; the design needs the snapshot to carry the intent version it was read for, so a snapshot read under N cannot be reused for N+1. Whether the existing `evidence_snapshot_id` and `intent_hash` pair in the decision key (`migrations/0027_decision_input_key.sql`) already enforces this is **not verified**; the first test of the task checks it.

**8. Slots N+1 does not name (the author's proposed safer default, awaiting the Architect's confirmation; not a ruling).** Decision 6 compiles the follow-up turn alone. A follow-up such as PUS-08's "It was 50k, not 20k" then names an amount and nothing else: no counterparty, direction or time. REQ-INT-004 lets only the latest version be evaluated, so N+1 must hold the whole intent, and design 5 has nothing to compare for a slot the new turn never names. The proposal: **the core (the gate), in the step that admits N+1, copies N's RESOLVED slots (already admitted through the gate) into N+1 for every slot the new turn does not name, and takes the new turn's value only for a slot it names.** Rules:
   - (a) It is deterministic core logic over stored data, not a model reading (INV-02). N is read from the store as the latest admitted version of the chain, under the verified session's tenant and principal (design 1), never from the turn or the model response.
   - (b) A slot N had not resolved stays unresolved in N+1. Nothing is invented to fill it.
   - (c) The copied slots go through the gate again as part of N+1 (node, slot contract, pack in force at N+1), not around it. If the new turn makes a copied slot invalid, N+1 is refused and N stays the latest.
   - (d) No contract change (the slots are the `intent-slot.v1` objects N already holds), no threshold, no dependency, no migration. Which slots were copied is derivable from N and N+1, which the Record links through `supersedes`; no new member is proposed.

   The alternative is that N+1 is only a partial intent and the decision gets the rest from N when it evaluates. It is not preferred: it makes "only the latest version is evaluated" (REQ-INT-004, the plan's done-when) untrue, it makes the controller's E3 check and the decision key (`intent_hash`, `0027`) cover less than the slots the decision used, and it puts the join of two versions in the decision path instead of at the admit gate.

## Tests first (each names its ID)

1. A follow-up with the right principal, right tenant and an open investigation, compiled alone (decision 6: the prior turn is not in the compile request), stores N+1 with `supersedes` (REQ-INP-004, REQ-INT-004, US-11).
2. A follow-up with another principal, another tenant and an unknown `conversation_ref` give byte-identical "not found" bodies and a security event for the first two (REQ-INP-004, EC-C03).
3. PUS-08 end to end over the real store: 20k then "50k, not 20k" gives N+1 that holds N's counterparty, direction and time (design 8), the flag, recomputed candidates, and the decision input names N+1 only.
4. Two concurrent follow-ups on N: exactly one N+1 is stored, and the loser is recompiled (REQ-INT-004; real Postgres, EC-C01/EC-C02).
5. A grant minted under N is refused at spend and execute once N+1 is admitted (lazy void, D8; reason `INTENT_SUPERSEDED`), and nothing is rewritten at admit time (REQ-INT-004, INV-03, INV-17; Record events asserted: `INTENT_ADMITTED`, `INVESTIGATION_RESUMED` and the void the controller writes at execution).
6. Property (REQ-INT-004): for any sequence of follow-ups, the stored versions of an intent are 1..K without gaps, each with `supersedes` to its predecessor, and exactly one is the latest.
7. A follow-up on a terminal investigation is refused and the customer is asked for a new request (A320, A404).
8. Evidence read before the resume is not used by the decision of N+1 (US-11).
9. A follow-up inserts N+1 under the chain's correlation id (the first turn's, not the request id), and `Latest` returns it (decision 7, `0026`, REQ-INT-004).
10. Slot inheritance (design 8; REQ-INT-004, REQ-INP-004, INV-02, PUS-08), over the real store and gate: (a) a follow-up that names only the amount keeps N's counterparty, direction and time; (b) a follow-up that names a counterparty replaces only that slot; (c) a slot N had not resolved stays unresolved in N+1 and nothing is invented; (d) the copied slots go through the gate again: a copy that the gate would refuse at N+1 refuses N+1 and leaves N the latest.

Faults: the store insert failing after the compile (nothing admitted, nothing voided), and the model service down (the follow-up fails closed with the open intent unchanged). Both come from the real store and a stopped service, not mocks.

5. **Rate and size of a conversation:** no cap (A404).
6. **How the compile call gets the prior turn (safer default taken, for the Architect to confirm; A666 does not strictly cover it):** compile the new turn alone, with no contract change; the gate compares N and N+1. The model sees nothing of the prior turn, so there is nothing to mask or to be injected through it. Nothing is added: no threshold, no dependency, no contract member.
7. **How N+1 carries the chain id (safer default taken, for the Architect to confirm; from EL's finding 1 at `3eecf0a2`):** the core writes the investigation's chain correlation id into the canonical input and the Intent Object of a follow-up; the request id stays the log and Record-event request id. No migration. **If the first red test shows this needs a migration or a contract change, the build stops and says so** (a migration is Tier 1 and needs an independent read, A463).
8. **How N+1 gets the slots N had resolved (the author's proposed safer default, for the Architect to confirm; EL's new finding 1 at `e10b29b9`):** the core copies N's RESOLVED, already-gated slots into N+1 for every slot the new turn does not name, takes the new turn's value only where it names one, and runs the result through the gate again (design 8). It is deterministic core logic, not a model reading (INV-02), with no contract change, threshold or dependency. The alternative (N+1 is a partial intent) is not preferred, for the reasons in design 8. **If the Architect prefers the alternative, design 8 and test 10 are rewritten before code.**

SR's asks for the build stand: any prior-turn text given to a model is masked (no account number, no digit run over four); tenant, principal and `conversation_ref` are written by the core from the session and never taken from the compile response; any new migration is Tier 1.
