## Session 2026-11-17 17:48 WAT · slice 1: the Trust-side refusal

### Session summary
- What changed (PR links): none yet (local commits only). `services/core/trust/recorder/recorder.go` (`ErrWritesDisabled`; the read and the refusal in `Write`), `kill_switch_test.go`, `doc.go`, and `services/core/trust/README.md`.
- Why: INV-03 and REQ-EXE-008: no grant is issued while the kill switch is on. Execution already voids a grant at spend when the switch is on (E6, E8); this stops the grant being issued at all.
- Risks, and how they are contained: (1) a check-then-write window. The read is a plain `SELECT` on the caller's transaction at READ COMMITTED; the Trust login has SELECT only on `tenant` (migration 0001), so it cannot `FOR SHARE` the row, and a switch turned on after the read and before the commit is not seen. Execution's re-read inside the spend voids such a grant (existing tests: `TestKillSwitchFlippedBetweenE6AndE8VoidsTheGrant`, `TestG2TheKillSwitchStopsTheCaseBeforeAnyWrite`); not proved again here. Closing the window in Trust would need a privilege or a lock the Trust login does not have: a migration, not done. (2) The switch is read only when the request has steps, so a decision with no step records as before. (3) A switch that cannot be read (no row, a database error) is an error and writes nothing; it is never read as off. That path has no test of its own: for a tenant with no row the database already refuses the write, so no test can tell the two apart; it is by reading only. (4) A retry of a stored decision with steps is refused while the switch is on (the check is before the stored decision is read): safer, and no grant of a stored decision is returned to a caller while the tenant is stopped.
- Tests added (REQ-EXE-008, REQ-OPS-002, INV-03; PUS-06), `trust/recorder/kill_switch_test.go`, real PostgreSQL with per-tenant `trust_rw` logins: (a) switch on, one step and two steps: `ErrWritesDisabled`, zero `GRANT_ISSUED`, zero decision rows, grants and Record events; (b) the refusal is made before the first write, checked inside the caller's own transaction; (c) switch on, an ALLOW with no step, a REJECT and a WAIT each still write their record and `DECISION_MADE`, no grant; (d) switch off is normal, on stops the next write, cleared writes again, two `GRANT_ISSUED` in all; (e) another tenant's switch does not affect this tenant, in both directions, and a tenant's own switch stops it; (f) the switch is read at write time inside the caller's transaction: READ COMMITTED sees a flip made after the transaction began; REPEATABLE READ sees its snapshot (pinned, see risk 1).
- Red run (before the fix, local, commit `0a16a69e`): the four tests (a), (d), (e), (f) failed on behaviour (`one step: err <nil>, want ErrWritesDisabled`; `3 GRANT_ISSUED events while the switch is on, want 0`); (c) and the no-step half of the rest passed already, as intended (they guard against over-blocking).
