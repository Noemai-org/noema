# orchestrator

**What it does.** Investigation projection, transition table and commands.

**REQs.** REQ-STM-001.

**Status.** G1 slice (11 Nov 2026): `ports.go` and `conversation.go`, the read-only runner of US-01 (`Runner.RunRead`: RECEIVED, INTERPRETING, EVALUATING, EXPLAINING, COMPLETED; every move applied by the Machine and recorded before the run goes on). STM-01 slice 1 built (7 Nov 2026): the table reader (`table.go`) and the pure state machine (`machine.go`). Not built: the `investigation` projection table, the optimistic-lock store, the `INVESTIGATION_STATE_CHANGED` Record event, the guards that need Trust, Execution or Outcome inputs. The import rules and prohibitions are in `doc.go`. `INPUT_RECEIVED` is written by the input gateway, never by the orchestrator (A161, relayed, to be committed): `RunRead` refuses a turn whose `InputReceivedRef` is not a Record event ID (`recev_` and 2 to 32 letters or digits) with `ErrNoInputReceived`, before it records or runs anything. The shape proves nothing, so `RunRead` also asks the `Admissions` port (a Record read as the session's tenant) for the event the reference names and runs only if it is an `INPUT_RECEIVED` of the session's tenant and principal and the turn's correlation; a missing event, a failed lookup or any mismatch is refused the same way.

**Write path (14 Nov 2026, A204, relayed).** `WriteRunner` (`runwrite.go`) adds `RunWrite` and `ResumeWrite` over three more ports, `WritePorts{Executor, Verifier, Journal}`, so `NewRunner` and the read path are unchanged. An ALLOW that writes walks PLANNED, EXECUTING (recorded after `Execute` returns), AWAITING_VERIFICATION, then EXPLAINING and COMPLETED on ACHIEVED, AWAITING_EXTERNAL_OUTCOME on PENDING_EXTERNAL, and RECOVERING then EVALUATING on NOT_ACHIEVED, PARTIALLY_ACHIEVED and COMPENSATED (a fresh snapshot, a new decision and grant), and RECOVERING and a stop with `ErrOutcomeUnknown` on UNKNOWN (a new grant could apply the same write twice). A lost reply is a `ReceiptUnknown`: verified by key, never dispatched again. A voided grant returns to EVALUATING. The recovery budget is an argument with no default; when it is spent a further allowed write is `ErrRecoveryBudgetSpent`. `ResumeWrite` continues from the stored projection and asks the Journal what the Record holds for the grant. Adapters (STM-03): `portadapters/executor` (over the Execution Controller), `portadapters/verifier` (over Outcome) and `portadapters/journal` (the Record-backed Journal: GRANT_SPENT and DISPATCH_ATTEMPTED, chain verified). **Debt, stated (for the Steward; the Architect's ruling is asked on noema#576):** (1) the recovery budget is a per-call argument, not persisted: a crash-and-resume loop that passes a fresh budget gets fresh recoveries, and an exhausted run stops in EVALUATING with `ErrRecoveryBudgetSpent`, a grant issued and not spent or voided, and no escalation state; the closing test is a resume that cannot exceed the budget of the run it continues, and an exhausted run that ends in ESCALATING. (2) A crash while the projection is EVALUATING or RECOVERING returns `ErrNotResumable` and the investigation stays stuck. (3) The RECOVERY_REQUESTED event of the state-machine document is not written by the runner (only the state change is): whether the Record can reconstruct a RECOVERING case is unconfirmed. (4) The decision is supplied by the caller to `ResumeWrite`; loading it from the Record is the Trust adapter's work. Not built: a plan of more than one grant.

**How it works.** `LoadTable()` reads the embedded `transitions.yaml`; `Machine.Apply(inv, cmd)` refuses a command made against another version (`ErrStaleVersion`), then an arrow that is not in the table (`*IllegalTransitionError`), then a refusing guard (`ErrGuardRefused`), and otherwise returns the investigation at `Version + 1` and the `Change` for the Record. A guard can refuse a listed transition and can never allow an unlisted one.

**Tests.** `go test ./orchestrator/...` from `services/core/`: the table equals the file, each unlisted pair is refused, a random-command property, malformed tables fail closed.

`transitions.yaml` is the state machine of PERD §28.2 as data (REQ-STM-001); `perd-28-2-state-machine.md` is the vendored PERD text it is tested against (`test_transitions.py`, run by `make contracts-validate`).
