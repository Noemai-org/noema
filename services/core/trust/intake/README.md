# trust/intake

**What it does.** The Trust intake assembles the steps T1 to T15 of PERD 23.3 into one service, `Service.Evaluate(ctx, Request) (Result, error)`. The order, the stop rules and the fail-closed behaviour are `trust/decide`'s (`EvaluateBound`); the intake supplies the step functions and reaches everything outside Trust through the interfaces of `ports.go`, so Trust imports no execution, evidence or understanding package (INV-01, SoT 51). The composition root supplies the adapters; EL's `Trust.Decide` adapter calls this service.

**REQs.** REQ-TRU-002 (fixed order, refuse before read), REQ-TRU-003 (T1 to T6 and T8 here), REQ-AMB-001 to REQ-AMB-004 (T7), REQ-CTX-003 (T9), REQ-RES-001 and REQ-RES-002 (T10), REQ-TRU-004 (T11), REQ-TRU-006 (T12), REQ-TRU-008 and REQ-TRU-009 (T13 to T15), REQ-NFR-002 (any failure is UNKNOWN, never ALLOW), REQ-TRU-011 (a typed request, not a conversation).

**Status (14 Nov 2026).** T1 to T15 are built. T1 to T6: the admitted intent (tenant, version, latest, verified), the session (tenant, principal, the intent's principal is the session's), the kill switch for a request that leads to a write, the requested capability (registered, not prohibited), scope, and the role (`Session.Role`, A205 Q5). T7 to T9 (`gates_t7_t9.go`, ports in `ports_t7_t9.go`) are the only steps that read about a target, each through its own port and nothing else:

- **T7 target resolution** (`Candidates`): a resolved intent passes and reads nothing. An unresolved one reads the candidates scoped to the session's principal and the pack's disambiguation data, keeps those at or above the floor, and builds the question with `decide.BuildClarification` (CLARIFY `AMBIGUOUS_COUNTERPARTY`), or ESCALATE `AMBIGUOUS_COUNTERPARTY` when none reaches the floor, more reach it than the pack's maximum, or no question can be built (one candidate, labels that do not tell the options apart). Scores are integers in the pack's unit: Trust decides on no float and holds no number.
- **T8 business ownership** (`Ownership`): a target the principal does not own and a target that does not exist are the same REJECT `NOT_FOUND_OR_NOT_AUTHORIZED`, with the same one port call and the same trace.
- **T9 evidence** (`Evidence`, with `Request.EvidenceSnapshotID` and `EvidenceUnavailable`, the orchestrator's `EvidenceRef`): an unavailable required source is ESCALATE `INSUFFICIENT_EVIDENCE`; an item past its effective limit that the Evidence Layer could not refresh is ESCALATE `STALE_EVIDENCE`; otherwise the snapshot and the freshness the port reported are recorded once in the evaluation's `BasisBuilder` and the step continues.
- **T10** asks the `Reconciler` port about the sealed snapshot (`Request.EvidenceSnapshotID` until T9 seals one) and stops with ESCALATE and the pack's reason code when the pack maps the classification to ESCALATE; a frozen target and a capability the pack does not allow under the freeze (`reconcile.FreezeGate`) never goes on (with no pack reason to escalate with it is UNKNOWN).
- **T11** asks the `Policies` port, records the deciding rules in the basis once (`BasisBuilder.RecordPolicy`), and ends REJECT, ESCALATE, CONFIRM (with the basis attached) or WAIT (with `reevaluate_at`) as the rule's effect says; no permitting rule is REJECT `NO_PERMITTING_RULE`. **Per capability (A306, interim):** for a write it asks once for each capability of the authorized set (the intent's own and the pack action graph's, sorted; read once for the evaluation by `Capabilities.Authorized`), so a capability the tenant's policy denies for the session's role ends the evaluation whichever step of the graph uses it; a read asks about the intent's own capability only. The answers combine in `policy_combine.go`: each capability first gets its own default deny (a PERMIT naming no rule, a REJECT with no reason, a CONFIRM with no PERMIT matched are REJECT `NO_PERMITTING_RULE`); the most restrictive effect wins (REJECT, ESCALATE, CONFIRM, WAIT, PERMIT, the order PERD 23.4 gives within a class); the first capability in sorted order that gave that effect supplies the reason code (two WAITs: the earliest `reevaluate_at`); `PermitMatched` holds only if every capability had a PERMIT; the rules and policy versions of every capability are recorded once each. PERD 23.3 and 23.4 are silent on the combination: this is the safer reading, not yet ratified. An unreadable authorized set, an error or an unusable answer for any one capability is UNKNOWN `INTERNAL_ERROR`. Consequence for policy data: every capability of a pack's action graph needs a PERMIT rule in the tenant's policy, or a write that reaches it is REJECT `NO_PERMITTING_RULE`.
- **T12** evaluates every clock the `Clocks` port names with `clocks.Evaluate`, at the evaluation's one clock reading and with the at-risk fraction from the port, and escalates only when the pack's routing says so. An input a clock cannot be evaluated from is UNKNOWN. Nothing about a clock is recorded in the basis.

- **T13 to T15**: T13 to T15 are built (`gates_t13_t15.go`, ports in `ports_t13_t15.go`): T13 asks the `Confirmations` port with `Status(ctx, intent, FreshBinding)`: `FreshBinding` is the two values of the confirmation binding (SoT 43.2a, INV-25) that only the fresh evaluation knows, the evidence set hash T9 kept from the Evidence port (`SnapshotEvidence.EvidenceSetHash`; T9 refuses a non-empty value that is not in the contract's hash form, UNKNOWN) and the `policy_id@version` of the one policy version T11 used (empty when none or more than one took part; empty values are passed on as empty, and the adapter refuses a Given answer for them). The statuses are `NotRequired`, `Pending`, `Given` and `Declined` (a decline is its own status and ends T13 in REJECT `DECLINED_BY_APPROVER`, SoT 43.2a, the Founder's order of 19 Nov 2026, interim). The answer also carries `RequestID` (the request the answer rests on) and, on Pending only, `NewRequest` (a `RequestSpec` of requirement and TTL, from the pack or the configuration; non-nil means no open request exists and Trust asks the Recorder port to create one with `RequestConfirmation`, the requester being the admitted intent's principal, INV-12; the id it returns reaches the caller as `Result.ConfirmationRequestID`). A confirmation the profile requires and that is not resolved stops with CONFIRM (a given one lets the evaluation go on and the grant follows its event; it must name the plan hash it was given for, **A230 interim**: a Given answer without a well-formed plan hash is UNKNOWN, and if the plan T14 builds has another hash the evaluation ends in UNKNOWN `PLAN_INVALID`, since T14's stop set is empty; the writer in `trust/recorder` refuses the same mismatch, noema#603); T14 asks the `Planner` port and validates the plan as plain values, an invalid plan being UNKNOWN `PLAN_INVALID`, and a read having an empty plan with its hash (A205, Q3); T15 builds the ALLOW with all three layers at PASS and the basis of the `BasisBuilder`, calls the `Recorder` port once, and lets the ALLOW stand only if it succeeded (record first, EC-E16). `Result` carries the decision ID and the grant IDs of an ALLOW. The composition implements `Recorder.Record` with `recorder.Writer` inside one transaction it owns. Known window: if the context ends while `Record` runs, the record may be written while the evaluation returns UNKNOWN; the composition's transaction is the place to close it.

Every step is built. T15 is the only step that can end in ALLOW, and only after the Decision Record is written by the `Recorder` port.

**Example.**

```go
svc := &intake.Service{Ports: ports, Clock: clk, PackVersion: "1.0.0"}
res, err := svc.Evaluate(ctx, intake.Request{
	Session: intake.Session{TenantID: t, PrincipalID: p, Role: role}, // from the authenticated session only
	CorrelationID: corr, IntentRef: "int_abc123@2",
})
// res.Decision.Outcome(), res.Decision.Reasons(), res.Trace (one entry per step reached)
```

A malformed reference is REJECT `INTENT_INVALID` and reads nothing. A missing port, no clock or pack version, or a context without a deadline is an error, never a decision.

**Tests.** `go test -race ./trust/intake/` from `services/core/`. `gates_test.go` and `target_ports_test.go` run whole evaluations through spies; `t7_t9_test.go` (package `intake`) builds the evaluation after T6 and runs one of T7 to T9 at a time.

**The second round of noema#572 (A224, A225, A254, A255, interim).** T10: a frozen target lets a read go on; a write the freeze blocks ends in ESCALATE `TARGET_FROZEN`, not an internal error. T12: a breached clock the pack's routing does not route escalates by itself, `CLOCK_BREACHED_UNROUTED`; then, for a write, the `Dispatches` port tells whether the logical write (the intent's capability and target, with the request's correlation) has used the ledger's budget, and Trust itself escalates `DISPATCH_BUDGET_EXHAUSTED` (the runner's refusal is only the backstop; the intake holds no limit, the ledger answers `Used` and `Limit`). It sits at T12 because PERD 23.3 gives T14 an empty stop set; the budget is asked for every capability the intent authorizes (below), not only the intent's own, so no plan step can receive an ALLOW grant for a spent one. T14: `Capabilities.Check(ctx, id, role)` is asked for the role of the session at every step, and a step the role may not use is UNKNOWN `PLAN_INVALID`. T15 hands the Recorder a sealed copy of the basis builder (`BasisBuilder.Sealed`).

**A306 (the per-step policy, after noema#572 merged; interim).** The authorized set below is also what T11 evaluates the policy for, see T11. The authorized set and the dispatch budget: a READ capability in the set is asked of the `Dispatches` port like any other, and the adapter must answer `Limit >= 1` for it; a `Limit` of 0 is not an answer and ends the evaluation in UNKNOWN (`policy_capabilities_test.go` pins both).

**The third round of noema#572 (Codex P1 and P2, C2's note; defaults pending the Architect's confirmation, interim).** `Capabilities.Authorized(ctx, intent)` is the set of capability IDs the intent and the tenant's policy authorize, as pack data (the core holds no capability ID, INV-14); the intake adds the intent's own capability, sorts it and reads it once per evaluation. T12 asks the dispatch budget for each of them (a spent one is ESCALATE `DISPATCH_BUDGET_EXHAUSTED`; fail closed, it may escalate for a capability the plan would not use). T14 refuses (UNKNOWN `PLAN_INVALID`, nothing recorded) a step whose capability is outside the set, after the registry, role and target checks, whatever the registry says; an unreadable set is UNKNOWN `INTERNAL_ERROR`. T15 refuses a Recorder answer that names a grant ID twice.

**TRU-12 (follow-up of TRU-07; the Founder's order of 19 Nov 2026, interim, relayed, not yet committed).** A CONFIRM carries the id of the request the approver answers as `Result.ConfirmationRequestID` (`decide.Decision` has no place for it; set for a CONFIRM only, never for an ALLOW): the open request's `RequestID`, or, for a `NewRequest`, the id the Recorder returned from `RequestConfirmation` (Status is pure; the Recorder persists the request and its CONFIRMATION_REQUESTED event; a Recorder error, no id or an id not in the `cfr_` form is UNKNOWN, and an answer that is both open and new, or a spec without a requirement or a positive TTL, is UNKNOWN). A `ConfirmationDeclined` answer closes the decision as REJECT `DECLINED_BY_APPROVER` (SoT 43.2a; T13's stop set is {Confirm, Reject} in `decide`), carrying the evaluation's basis, with no new request, no plan and no grant. A zero or unknown status stays UNKNOWN `INTERNAL_ERROR`, and a Given confirmation for another plan stays UNKNOWN `PLAN_INVALID` (A230).
