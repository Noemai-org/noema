# edge/events

**What it does.** The server-sent events route of the public API (EDG-02, ruling A170): `GET /v1/conversations/{conversation_ref}/events` streams `sse-event.v1` payloads (`progress`, `clarification`, `confirmation`, `answer`, `error`; PERD 39.2, `contracts/schemas/sse-event.v1.json`). An `Event` holds a cursor and exactly one payload; the handler sets the payload's `event` name and `schema_version` itself, round-trips it through its generated strict decoder, requires canonical UTC instants, and refuses (as `INTERNAL_SAFETY_BLOCK` in an error event, writing nothing of the event) any text the injected masker would change: the contract's texts carry no run of five or more digits (A154). The three IDs a card carries are checked by their contract shape and exempt. It writes only what a `Feed` returned as committed state (PERD 40), asked as the verified session's principal and tenant (INV-12); a conversation that is not the caller's is the same 404 as one that does not exist (REQ-API-002). `Last-Event-ID` resumes after a cursor; a malformed one is 400. A feed failure after the stream began is an error event `DEPENDENCY_UNAVAILABLE` (retryable); a keepalive comment is sent when a poll returns nothing. Pre-stream errors are the `errors.v3` envelope.

**REQs.** REQ-API-001, REQ-API-002, REQ-SEC-003. SoT: INV-12, AGENT-13.

**Not here.** The Feed over the Record is `cmd/core/wire_events.go` (progress events only; no Record payload carries card or answer content yet, see `status/EDG-02-wire-events.md`); the mount line (the final main.go PR).

**Tests.** `go test ./edge/events/` from `services/core/` (no database).

**Lifetime and limits.** A stream never outlives the session's token (the smaller of `MaxStream` and the token's remaining life by the injected clock); a token at its expiry gets 401. Each write has a deadline (`WriteTimeout`) and a failed write ends the stream. Open streams are capped overall and per tenant and principal; a refused stream is the retryable 503 `DEPENDENCY_UNAVAILABLE`. A Feed answer over `MaxBatch` is a bad answer. The handler checks the `customer` role itself. A writer that cannot take a write deadline gets 500 `INTERNAL_SAFETY_BLOCK` and no stream. The response carries `X-Accel-Buffering: no`. Every limit is configuration with no default (AGENT-16).

**Stated limits.** (1) The generated decoders check shape, not patterns or bounds (`internal/contracts/doc.go`): `minItems` and string lengths are the Feed's to satisfy. (2) A session closed or revoked mid-stream is not noticed; only its expiry ends the stream. (3) `MaxBatch` bounds what is written, not what the Feed builds.
