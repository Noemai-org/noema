# evidence

**What it does.** The read-only Evidence Layer: items, freshness, candidates API.

**REQs.** REQ-CTX-001, REQ-CTX-002, REQ-CTX-003.

**Status.** EVD-01 slice 1 (the task card is docs#109, merged): `layer.AssignStatus`, the pure and total FactStatus function of REQ-CTX-002, with tests (a table of the PERD §21.1 rows it can decide, absence never KNOWN, whatever a source declares (PERD §21.1's AUTHORITATIVE_NEGATIVE exception is not built: evidence-item.v1 forbids it and evidence-source.v1 has no field to declare it), totality and determinism over 50,000 seeded generated reads, and a Go fuzz target). It returns KNOWN, STALE, UNAVAILABLE, UNKNOWN or UNAUTHORIZED; INFERRED, AMBIGUOUS and CONTRADICTORY need more than one item and a reconciliation rule (RES tasks). Slice 2a (noema#167) adds the `evidence_item` and `evidence_payload` tables (migration 0008, insert-only, bound to the login's tenant). Slice 2b adds `layer.Builder.Record`: it assigns the status, hashes the payload, stores payload and item and appends an `EVIDENCE_READ` event (hash only) in one transaction on the tenant's evidence login. Not built yet: the mapping from a real adapter error to a read class (slice 2c), refresh, snapshots and the candidates API (EVD-01 slice 2 onward, EVD-02 to EVD-06). The import rules and prohibitions are in `doc.go`.

**Decisions (the card's D1 to D5, reversible).** A value from a corroborating-only source, from a source with authority NONE, or read from the future is UNKNOWN; the rules run most restrictive first; the function lives in `layer`.

**Tests.** `go test ./evidence/...` from `services/core/`; fuzz with `go test -fuzz FuzzAssignStatus ./evidence/layer/`.

**EVD-03 (sealed context snapshots, REQ-CTX-004, INV-17).** `snapshot/`: `SetHash` (the evidence_set_hash against the golden vectors), `Sealer.Seal` (sorts and hashes the set, refuses the empty set, appends `CONTEXT_SNAPSHOT_SEALED` and stores the row in the caller's transaction), and `Recompute` (the nightly check: every stored hash recomputed from the stored items, run as the read-only `evidence_verify` login; its output carries tenant, snapshot and digests only). The table, its guard trigger and the login's grants are migration 0020; see `snapshot/README.md`.

**EVD-06 slice 2 (the advisory injection detector, REQ-CTX-007, ruling A292).** `injection/`: the loader of the pattern list in pack data (`packs/fintech/context/injection_patterns.v1.json`), `Detector` (field names and pattern ids, never text; a value is cut to the cap before any pattern runs), `Screener` and the `Recorder` port, and `RecordRecorder`, which appends `SECURITY_EVENT` of kind `INJECTION_DETECTED` as `core-evidence`. Advisory only; not yet called from the read path. See `injection/README.md`.

**EVD-02 (effective freshness, REQ-CTX-003, INV-23).** `freshness/`: `Effective` (the strictest of the source's limit, the trust profile's limit and a per-source override, and which of them set it: `limit_set_by`), `Check` (the age from `read_at` on the injected clock; STALE only when OLDER than the limit, so exactly at the limit is fresh, PERD 21.1), and `Session` (one evaluation: a stale source is re-read at most once, a failed, still-stale or unrecordable refresh makes the source UNAVAILABLE and returns no item, and `EVIDENCE_REFRESHED` goes to a `Sink` before the refreshed item is used). `layer.effectiveLimit` delegates to `freshness.Effective`. Not built: the `Sink` that appends `EVIDENCE_REFRESHED` to the chain, and the call from Trust's read path (the next slice; see `status/EVD-02.md`). No freshness value is set here: the limits come from the pack.
