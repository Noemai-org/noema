# record/payloadguard

The write-side guard of the Record (A184, A193, A194, A201) and the one definition of a run of digits.

- **What it does.** `Check` refuses a payload whose strings hold a run of more than `Limit` (4) digits, with typed exemptions (A193). `Mask` keeps only the last `Limit` digits of every run of a string; `record/reconstruct` serves its facts through it and keeps no regexp of its own (A194).
- **One definition, one set (A231, interim).** `separators` is the one set that joins digits: every kind of space (`\p{Z}`, the vertical tab, the next-line character), every dash (`\p{Pd}`) and the minus sign, every bracket (`\p{Ps}`, `\p{Pe}`), the dot, slash, colon and underscore with their full-width forms and the middle dots, every format character and every combining mark. A comma is not in it (an amount like `20,000,000` is not one run). The guard refuses by `digitRun` and the display mask masks by the same `digitRun`: there is no second mode, so a number split by an underscore, a colon or a bracket is refused at append and masked on display. **The one exemption (A231):** a short `UPPER_SNAKE` reason code, whole-string, with at most 6 digits and at most 3 in a group (`VERSION_CONFLICT_409_412` passes; `X_4111_1111_1111_1111` does not). **A deviation for the Architect to confirm:** the Record stores the receipt's `raw_status` as `<transport result>[:<raw code>]` (for example `VERSION_CONFLICT_409_412:409`), which the bare shape would refuse (and so refuse the receipt of every version conflict, after the write was dispatched); the exemption therefore also takes up to two colon-separated raw-code parts (one to three digits, or an UPPER_SNAKE word with no digit) and at most 9 digits in all.
- **The limit** equals the one number of `masking-limits.v1` (`TestTheGuardsLimitIsTheMaskingLimitOfThePack`).
- **REQs.** REQ-AUD-003, REQ-SEC-003; A154, A184, A193, A194, A201.
- **Tests.** `go test ./record/payloadguard/ ./record/reconstruct/`.
