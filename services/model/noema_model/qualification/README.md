# noema_model/qualification

**What it does.** Two things for REQ-INT-006 (model-drift canary; D25, AGENT-28): `gate.py` is the check that refuses a model ID with no QUALIFIED record or an unpinned version (`require_qualified` is the start-up check; **nothing in the service calls `require_qualified` or `run_canary` yet**, so no model selection is gated by this slice alone: wiring it is the next UND-13 slice, and UND-13's done-when is not met until then); `canary.py` sends the qualification subset through the service's own provider adapters and emits the run record (`qualification-run.v1`) with PASS, DRIFT (with the differing slots and the version that answered) or PROVIDER_UNAVAILABLE.

**Formats and rules** belong to the benchmark's `benchmark/qualification/` module (its README). The tests here run SYNTHETIC records and run records that module produced (`tests/fixtures/qualification/*_golden.json`) and require identical results. If the benchmark module changes a format, regenerate the fixtures; the tests fail until the two agree.

**Limits.** No held-out or partner case reaches this package (INV-22): a subset outside the GENERATED layer is refused before any call. The canary never decides that a drift is acceptable or that a version is qualified (that is the qualification record's decision record). No timeout is chosen here (AGENT-16): `run_canary` takes `timeout_s` from configuration. The prompt and schema for a case belong to the pipeline: `noema_model/harness/canary_asker.py` (`ProviderAsker`, in the harness because only the harness imports providers) takes a `build` function.

**Wiring (not in this slice).** Calling `require_qualified` at service start with the configured providers, and running the canary on a version or provider change, are the service's start-up and operations wiring; they need the harness configuration to name a records directory and a subset, which is a configuration decision (OD below in the PR).

**Tests.** `pytest tests/test_qualification_gate.py tests/test_qualification_canary.py` from `services/model/`.

**Fail closed on a malformed record (EL's review of noema#215).** A rate, a floor or a baseline that is NaN, infinite, a bool, a string or outside 0..1 invalidates the record, so the identity is refused (every comparison with NaN is false and would otherwise pass); a digest or date with a trailing newline is not a digest or a date (`fullmatch`); a reason that is not a string invalidates the record instead of raising. `run_canary` refuses a `timeout_s` that is not a positive finite number. A refused, truncated or unparseable reply is still recorded as UNAVAILABLE for that case, so a drifted answer shape reads as an outage in the run record (recording the reason per case is a later change). `gate.py` imports `harness.config` for the pin rule (`check_pinned`); that is the only import beyond the standard library and `platform`.
