# noema_model/understanding/compiler

The model service's compile route (UND-05, slice 1; REQ-INT-001, REQ-INT-002, REQ-INT-005, REQ-API-002; INV-02, INV-12, AGENT-09). Updated 13 Nov 2026. All data is SYNTHETIC.

**What it does.** `POST /internal/v1/understanding:compile` takes `{canonical_input, pack_ref, open_intent?}` (the core's compile request) and answers `{intent_object, canonical_input}`, or an `errors.v2` envelope. `CompileService` calls a `Compiler`, holds its reply to the schema gate (`../gate`) and returns the gated proposal. The route never repairs, signs or hashes a proposal (ruling A166).

| Case | Answer | Code |
|---|---|---|
| a request that is not the contract's (wrong shape, duplicate member, canonical input not major 2, a pack this service does not hold, identity not in shape) | 422 | `INPUT_INVALID`, not retryable; no compiler is called |
| no compiler wired in this process | 503 | `DEPENDENCY_UNAVAILABLE`, retryable (the route exists; it cannot serve yet); the body is not read |
| a body over `max_request_bytes` (declared length, or counted as it streams), or a malformed `Content-Length` | 413, 422 | `INPUT_INVALID`, not retryable; a declared length over the bound is refused before one byte is read |
| the compiler found no usable provider reply, or its reply fails the schema gate | 502 | `PROVIDER_UNAVAILABLE`, retryable; the reply is never repaired |
| the compiler exceeds the configured deadline | 502 | `PROVIDER_UNAVAILABLE`, retryable |
| any other exception (a bug) | 500 | `INTERNAL_SAFETY_BLOCK`; a bug is never hidden as a provider failure |

**Identity.** The gate is held to the canonical input's own identity: `tenant_id`, `correlation_id`, `session_id` and `principal_ref`, which the core sets from the session. A proposal that carries `principal_type`, `asserted_by` or `sig` is refused by the gate. An envelope's message never carries text of the request.

**Configuration.** `CompileService(compiler, packs, max_proposal_bytes, timeout_s, max_request_bytes)`: the three numbers must be positive and come from configuration (AGENT-16); there is no default.

**The lexicon and the normaliser** (`lexicon.py` and `packs/fintech/lexicons/fin.lex.en_ng.json`, slice 4; REQ-INT-003; INV-14, INV-21; AGENT-16, AGENT-25; PR noema#584; the file's shape is proposed on noema#583). `Lexicon` is pack data: the currency, the multiplier words (`k`, `thousand`), the relative-time phrases with their windows, the direction words and a fixed UTC offset (WAT, no `zoneinfo`). **Every entry is a `[synthetic seed]`**, not reviewed by a native speaker (OQ-12); the loader refuses an entry without the mark, and the numbers move only through a benchmark run and a founder decision. `Normaliser(lexicon, received_at).normalise` is the pipeline's `Normalise` seam, built per request with the canonical input's `received_at` (the core's clock, so replay gives the same window). **Its values win over the model's and nothing is invented:** an amount, a time or a name that the customer's own words do not hold is left unread. v0 reads digits only (`20k`, `20,000`, `20 thousand naira`, `₦20,000`), in minor units, whole minor units only, under the contract's safe integer; `sharp-sharp` is never an amount; `twenty thousand` is UND-06's. The day is the local day, not the UTC day.

**The assembler** (`assemble.py`, slice 2; REQ-INT-001, REQ-INT-003, REQ-INT-005; PR noema#581). A pure function, `assemble(canonical_input, pipeline_result, catalogue, pack_ref, identifiers) -> bytes`: the bytes of an `intent-object.v3` proposal (status EXTRACTED, no `sig`, no `principal_type`, no `asserted_by`; compact JSON, keys sorted, no float). No clock, no randomness, no I/O.

| Member | Where it comes from |
|---|---|
| `tenant_id`, `correlation_id`, `principal.principal_id` (`principal_ref`), `principal.authn_ref` (`session_id`), `source.mode`, `source.channel` | the canonical input only; the model's text never reaches them (INV-12) |
| a Quantity slot's `value` and `unit`; a TimeRef slot's `window` | the deterministic lexicon (REQ-INT-003); a mention it cannot read is **left out, never guessed** |
| the Resource slot | the ranking: RESOLVED only with a `resolved_ref` (INV-06); AMBIGUOUS and TOO_MANY are AMBIGUOUS; no match is UNRESOLVED; the candidate set id must be the contract's `cns_…` or the call is a bug (`ValueError`) |
| every `confidence` | the model's, floored to integer basis points and clamped to 0 to 10000 (A173) |
| Reference slots | the model's closed-vocabulary choice |
| `intent_id`, `version`, `supersedes`, `created_at`, `source.raw_ref` | one `Identifiers` argument: **nobody owns them yet** (noema#580) |
| `desired_outcome_refs` | always empty: the model never proposes an outcome (INV-01) |

**The model's words are bounded before they enter the object** (the Security Reviewer's blocking finding on noema#598). A surface form of a party, a time or a quantity is copied only if it is a span of the text the model was given, no longer than the lexicon's bound (`MAX_SURFACE`, 64) and holding no run of more than four digits unless the whole of it is an amount such as `NGN 12,345.00` (`noema_model.platform.redaction.money.is_money`, A308 interim) (the Record guard's definition of a run, `separators` of `record/payloadguard` in noema#600 at its head `75beb587`, A194 and A231: Unicode decimal digits in any script joined by any number of spaces of any kind, dashes (`Pd`), brackets (`Ps`, `Pe`), format characters, combining marks, dots, slashes, colons, underscores, the minus sign, the middle dots and the full-width dot, slash, colon and low line; `noema_model.platform.redaction.digit_runs` holds the one definition (the union of that set, of the guard on `main` and of the contracts' public-API pattern, so it is never looser than any of them) and the assembler imports it; a comma, a plus sign and a letter end a run). Otherwise a party or a time slot is left out and a quantity keeps the lexicon's value without a quotation. **Consequence, stated for the Architect:** an amount the customer writes with a run of five or more digits (`50000`) keeps its value but loses its surface form, because the Record would refuse such a string; if the quotation should be kept in a masked form, that is a decision, not mine.

An out-of-scope or unclear request compiles to the out-of-scope node with its flag and no slots (an unclear request is read as out of scope: a default, noema#546); **a rejected result is never assembled** (REQ-INT-002). A node with two slots of one lexicon type (two amounts, two windows, two counterparties) is refused.


**The pack loader** (`packconfig.py`, slice 3; REQ-AMB-002, REQ-AMB-003, REQ-INT-005; INV-14, INV-21; AGENT-16; PR noema#582). `load_pipeline_config(pack, pack_dir, out_of_scope_node=...)` returns the pipeline's `PipelineConfig` from the loaded pack JSON: the `understanding` block (ranking weights, floor, tolerances; proposable flags; locales; material flags; the two named flags; the state-to-flag map), the candidate node's `disambiguation` (the margin and the limit of candidates stay there, where the SoT shape puts them) and the matcher file the pack names. **Nothing is defaulted.** A pack that is not whole fails at load, not at the first request: a missing, unknown, repeated or badly shaped member; an unknown ranking state; a margin outside 0 to 1; a limit that is not a positive integer; zero or two candidate nodes; a margin or limit also written in `ranking`. A `matcher_ref` that leaves the pack's folder (absolute, `..`, a symlink out) is refused. A JSON number for the margin is read as its shortest decimal (`0.35` is exactly 7/20, not the binary 0.34999...). The yes threshold of a native decision model stays unset: a benchmark and a founder decision set it (AGENT-16).

**The compiler** (`compiler.py`, slice 5; REQ-INT-001, REQ-INT-002, REQ-INT-003, REQ-INT-005; INV-01, INV-02, INV-12, INV-21, INV-29). `PipelineCompiler(packs, lexicon, harness, source, minter)` is the `Compiler` the service calls: it builds the pipeline's input from the canonical input only, runs the pipeline with the lexicon's `Normaliser` (reference instant: the canonical input's own `received_at`), and assembles the result. Same request, same bytes. It calls no provider itself: the harness does, behind `providers/`.

**The lexicons of a pack (UND-16, run #6; A532).** `load_pack_lexicons(pack, directory)` reads the files the nodes name in `lexicon_refs` (`<directory>/<ref>.json`, its own `lexicon_id` the ref, a ref never a path) and merges them (`merge_lexicons`): they must agree on the offset and the currency, and a word or phrase two of them define must mean the same; anything else is refused. A ref with no file (`yo`, `ha`, `ig` today) is skipped, as it always was; a pack none of whose refs has a file is refused. `fin.lex.pcm` holds the Pidgin phrase `dis morning`; the English file never holds a Pidgin phrase. The file is pack data, minimal and labelled SYNTHETIC (A538). **A request with no time reference is not refused (A535, interim)**: nothing is read, the `when` slot is absent (a `TimeRef` needs the customer's words) or `UNRESOLVED` when the lexicon could not read them, the resource slot is `UNRESOLVED` with no candidate set, and Trust asks. A section of a lexicon file may be absent. **`InputInvalid` carries a closed `reason`** (`InputInvalidReason`: `NOT_FINAL_TRANSCRIPT`, `CANDIDATE_REQUEST_INVALID`, `UNKNOWN_PACK`, `NOT_TEXT_CHANNEL`, `BAD_RECEIVED_AT`, `IDENTITY_INVALID`), for the service's own accounting and the benchmark's failure text; the public answer is `INPUT_INVALID` for all of them and names none.

**The wiring** (`wiring.py`; REQ-INT-001, REQ-API-005, REQ-SEC-002; INV-29, AGENT-16). `create_app` builds the compile service only when `NOEMA_MODEL_COMPILE_CONFIG` names a JSON file; otherwise nothing changes and the route answers 503. With it named, **every member is required and none has a default**: `pack_file`, `lexicon_dir`, `out_of_scope_node`, `timeout_s`, `max_proposal_bytes`, `max_request_bytes`, `evidence` (`endpoint`, `timeout_ms`, `max_response_bytes`) and `evidence_tls` (`cert_file`, `key_file`, `ca_file`); an unknown, repeated or out-of-range member, a pack the catalogue cannot load, or a harness that was not built refuses to start. It also refuses unless `UVICORN_SSL_CERT_REQS` is exactly `2` and the certificate, key and CA settings are set (the image's, noema#568). The Evidence link is the service's own mutual-TLS transport (`NOEMA_MODEL_EVIDENCE_POOL_SIZE`, no default). The pack the gate checks is read from the pack file itself (`<pack_id>@<pack_version>`); no node of it defines an outcome, so a proposal that names one is refused (INV-01). **`DerivedMinter` is a default for noema#580, not an answer to it:** `intent_id` is `int_` and 26 letters of a hash of the tenant, the correlation and the client's request id; `version` 1; `created_at` is `received_at`; `raw_ref` is the neutral marker `unset`, which **the core must overwrite with its own object reference** (the Interpreter adapter, noema#565) before a G1 run: until then a stored intent would carry `unset`. The candidate set id is derived the same way. **Not here:** the core's candidates endpoint (`POST /internal/v1/evidence/candidates`) has no handler yet (`evidence/candidates_api` is only a package comment), so a compile that needs a candidate read answers `PROVIDER_UNAVAILABLE` against a real core until it exists.

**Preconditions before any PR sets `compile_service` in `main.py`** (Security Reviewer's review of noema#544; none is reachable while no compiler is wired, and the route then answers 503 and compiles nothing):
1. **Peer authentication.** Nothing enforces who may call the listener today but the network (`svc_net`, internal). mTLS on the model's listener is tracked on noema#555 and must be closed first. **The wiring below refuses to build a service unless the process's own listener settings require a client certificate** (`require_mtls_listener`); it is not a proof of the peer.
2. **A concurrency cap** from configuration, and a test that `asyncio.wait_for` cancels the provider call so it cannot leak.
3. **Masking and validation at this boundary.** A masking guard (A184, `masking-limits.v1`) or the core's stated guarantee that `canonical_input` is already masked; `open_intent` is an unvalidated object passed to the compiler and must be validated; the provider-terms gate (REQ-INT-006).
4. **The echoed `canonical_input`** is the request's own: the core must never trust it as the session's.
5. **Reasons.** The gate's reasons never leave this service (a refusal is `PROVIDER_UNAVAILABLE`). If they are ever logged or recorded, the model-side reason for a model-set identity member (`SHAPE`) moves to the core's `IDENTITY_SET_BY_MODEL` (ruling A195).

**Tests.** `pytest tests/test_compile_route.py tests/test_intent_gate.py` from `services/model/`. `mypy --strict` is clean.
